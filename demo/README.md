# 데모 콘솔 (SCRUM-290 / SCRUM-310 / SCRUM-311)

AI 서버가 자기 파이프라인을 설명하는 개발·데모용 화면이다. 탭이 셋이다.

- **콘텐츠 검수** — 검수 한 건이 N0 규칙부터 N5 확정까지 **어디를 지나는지** 따라간다.
- **리뷰 요약** — 리뷰 묶음이 입력 게이트 -> 추출 -> 집계 -> 서술 -> 출력 게이트를 지나는
  동안 **무엇이 남고 무엇이 떨어지는지** 따라간다.
- **셀러 폼 초안** — 같은 상품명을 **두 입력 방식으로 나란히** 돌려 비용·지연·초안을
  한 화면에서 비교한다. 입력 방식이 아직 미결이고 사람이 그 표를 읽고 고른다.

어드민 검수 화면은 범위가 아니다(그쪽은 SCRUM-283, FE가 맡는다).

```bash
uv run python -m demo              # http://127.0.0.1:8100
uv run uvicorn demo.app:app --port 8100
```

기본 모드는 **재생**이다. 키가 없어도 돌고 비용이 0이다.

## 왜 별 프로세스인가

운영 앱(`app/main.py`)에 라우트를 붙이지 않는다. 근거 셋이다.

1. `app/main.py` 가 "HTTP로는 헬스체크만 공개한다. 공개 ALB 뒤에 있으므로 관리용 경로를 열어
   두면 이름이 internal이어도 외부에서 닿는다"고 명시하고 `docs_url` 까지 끈 상태다. 콘솔을
   거기 붙이면 **인증 없는 콘솔이 공개 ALB에 선다.**
2. Dockerfile이 `COPY app` 과 `COPY prompts` 만 한다. 그래서 `demo/` 는 **운영 이미지에 애초에
   들어가지 않는다.** `harness/` 가 이미 같은 규칙으로 밖에 있다.
3. **새 의존성이 0이다.** FastAPI와 uvicorn은 이미 main 의존성이라 `uv.lock` 이 그대로다.
   Streamlit을 쓰면 pandas·pyarrow·altair가 따라오고, `[project.dependencies]` 에 넣는 순간
   운영 이미지에 실린다. 비기본 그룹으로 빼도 락파일 전체가 다시 해석된다.

`tests/test_demo.py` 의 `test_운영_...` 셋이 이 배치를 지킨다 — Dockerfile이 `demo` 를 담지
않는 것, 운영 의존성 목록이 그대로인 것, 운영 앱에 콘솔 경로가 없는 것.

## 모드 넷

| 모드 | 모델 호출 | 쓰는 자리 |
|---|---|---|
| **재생**(기본) | 없음. 손으로 쓴 카세트 | 탈출 지점 여덟을 보여 주는 발표 경로 |
| **모의** | 없음. 키워드 표로 답하는 대역 | 사람이 자기 문장을 넣어 보는 자리. 판정은 모델 판단이 아니다 |
| **라이브** | 실제 호출. 돈이 든다 | 키가 있을 때만 켜진다 |
| **저장된 판정** | 없음. 판정 JSON을 다시 그린다 | 기록된 판정의 모양을 되살릴 때 |

### 재생이 모델 **경계**에서 되돌리는 이유

판정 JSON 하나를 다시 그리는 얕은 재생으로는 보여 줘야 하는 것의 절반이 나오지 않는다.
선별 사유와 결정·단계 라벨·실패 상세가 판정 계약에 없기 때문이다. 그래서 `call_tool` 만
구현한 `ReplayLlmClient` 를 끼운다. 그러면 **실제 파이프라인이 그대로 돌아** 추적 전체가
생기고, 결정론적이며 비용이 0이다. 이 이음매는 이미 열려 있었다 — 파이프라인은 `llm` 을
덕 타이핑으로 `call_tool`/`aclose` 만 부른다. **운영 코드는 한 줄도 바꾸지 않았다.**

카세트 키는 호출 순서가 아니라 **(툴 이름, 관점)** 이다. 순서로 두면 분기가 바뀔 때마다
조용히 어긋난 응답이 흘러 들어간다. 없는 키는 `CassetteMiss` 로 터뜨린다 — 선별이 실패를
승급으로 접기 때문에, 빠진 카세트를 조용히 실패로 돌리면 콘솔이 거짓 단계를 그린다.

### 모의는 모델이 아니다

`demo/mock.py` 는 키워드 표로 답하는 결정론적 대역이고 토큰·비용은 글자 수에서 뽑은
추정값이다. 인용은 반드시 본문에서 떼어 온다 — 꾸며 쓰면 인용 검증이 그 판정을 버려
전건이 `EVIDENCE_UNVERIFIED` 로 떨어진다.

**판정이 추정값이라는 것을 결과 패널 머리줄이 말한다.** 모의 모드에서는 `모의 판정` 배지와
"이 판정은 키워드 표가 낸 것이다. 모델 판단이 아니다"가 함께 뜨고, 백엔드 게이트 배지는
중립색으로 내려간다. 종전에는 모의임을 알리는 표시가 원장 밑의 "토큰과 비용은 추정값이다"
한 줄뿐이라 **판정**이 추정이라는 경고가 없었고, 그 상태에서 사람이 자기 문장을 넣으면
결과가 "이 시스템은 이것을 이렇게 판정한다"로 읽혔다.

**모의 선별은 표에 안 걸리면 `NEEDS_REVIEW` 다.** 실제 프롬프트의 "확신이 서지 않으면
NEEDS_REVIEW" 와 같은 방향이다. 대역은 깨끗함을 증명할 수 없고, 표에 안 걸린다는 것은
"표에 없다"는 뜻일 뿐이다. `CLEAR` 는 깨끗하다고 적어 둔 표본 문구
(`mock.CLEAR_SAMPLE_MARKERS`)에만 낸다 — 종전에는 반대 방향이어서 정책의 위반 예시 그대로를
넣은 리뷰가 선별 통과 + 백엔드 게이트 통과로 떨어졌다.

### 키가 들어오면

`harness/run.py` 에 `--record` 를 더해 각 호출의 kwargs와 `LlmResult` 를 덤프하면 손으로 쓴
카세트를 실측 카세트로 갈아탈 수 있다. 하네스가 이미 모드별로 전 케이스를 돌리므로 덤프
지점은 `_run_pipeline_mode` 한 곳이다.

## 화면이 가르는 것

**통과(CLEAR)와 미검사(UNCHECKED)를 색과 라벨 양쪽으로 가른다.** 이것이 수용 기준이고
프로젝트 전체의 불변식이다. 그래서 단계 줄이 축을 둘 든다.

- `status` — 돌았는지 / 건너뛰었는지 / 걸렸는지 / 도달하지 않았는지
- `outcome` — 통과 / 미검사 / 위반

둘을 한 값으로 합치면 "아무도 안 봤다"가 "문제 없다"와 같은 색으로 그려진다.

탈출 지점 여섯(+둘)은 `ContentVerdict` **하나만으로** 갈린다. 그래서 추적이 없는 얕은
재생에서도 배지가 나온다.

| 탈출 | 판별 |
|---|---|
| 규칙 차단 | `FLAG` + 원장이 빔 + RULE 행이 VIOLATION |
| 선별 통과 | TRIAGE 행이 `CLEAR` |
| 선별 확정 위반 | `FLAG` + TRIAGE 행이 `VIOLATION` |
| 모델 위반 없음 | `PASS` + 모델 관점 **전부**가 실제로 판정 |
| 부분 미검사 통과 | `PASS` + 모델 관점 가운데 `UNCHECKED` 가 하나라도 있음 |
| 확정 위반 | `FLAG` + 모델 호출이 있음 + TRIAGE 행이 `VIOLATION` 이 아님 |
| (판정 실패) | `FAILED` |
| (stub 모드) | `FAILED` + `LLM_DISABLED` |

**부분 미검사 통과를 따로 둔 이유.** 집계가 통과를 내는 조건은 "**한** 관점이라도 판정했고
위반이 없다"다. 그래서 의료·효능 주장을 보는 유일한 관점이 인용 검증 실패나 레이트 리밋으로
죽어도 판정은 `PASS` 다. 그 둘을 한 배지로 합치면 머리줄이 "관점이 실제로 읽고 위반을 찾지
못했다. 이 통과는 미검사가 아니다"로 사실의 반대를 단정한다. 이 탈출의 설명문은 고정 문장이
아니라 관점 행에서 센 수치다 — "쏜 관점 2건 중 1건만 읽었다".

**재생은 환경변수를 한 칸도 읽지 않는다.** `Scenario` 가 파이프라인 모양 전부
(`enable_triage`·`perspective_fanout`·`enable_notice`·모델 ID 셋)를 들고
`Scenario.settings()` 가 리터럴에서 조립한다. 그리고 `_run` 이 끝에서 실제 탈출 지점을
`expected_exit` 와 맞춰 보고 어긋나면 화면을 그리지 않고 400을 돌려준다 — 종전에는
셸에 `AECHAK_AI_PERSPECTIVE_FANOUT=false` 가 있으면 네 시나리오가 카세트 미스로 죽었고,
그 실패가 사이드바의 `expected_exit` 와 어긋난 채로 정상 응답으로 나갔다.

**백엔드 게이트 배지**는 별 축이다. 백엔드 `InspectionFacade.modelVerified()` 를 그대로 옮긴
술어로, 이 통과를 관리자 확인 없이 반영할 수 있는지 답한다. 그 거울은 이 레포에
**하나뿐이다**(`view.backend_accepts`) — `tests/conftest.py` 가 그것을 import 한다. 사본을
둘 두고 "둘이 같은 답을 내는지" 보는 테스트는 항진명제였다(정본이 바뀌어도 둘은 서로 같다).
정본과의 어긋남은 계약 표본마다 게이트 통과 여부를 적은 표가 잡는다. 통과가 아닌 판정에는 적용되지
않는다(보류와 실패는 어차피 사람이 본다).

저장된 판정에서 `content-verdict-triage.json` 을 고르면 그 배지가 **불통과**로 뜬다.
백엔드가 소유한 그 표본이 모델 관점 행 없이 `[RULE/CLEAR, TRIAGE/CLEAR]` 로만 적혀 있어
생산자보다 뒤처져 있기 때문이다. 자세한 것은 `tests/contract/README.md` 에 있다.

## 추적은 계약 밖이다

콘솔이 보여 주는 "왜"는 `ContentVerdict` 에 없다. 그 계약은 백엔드 message 모듈과 1:1이라
필드를 더하면 백엔드가 **에러 없이** 모르는 필드를 버린다. 그래서 `app/inspection/trace.py` 의
인프로세스 객체로 모은다.

**추적기를 주지 않으면 아무 일도 일어나지 않는다.** 카프카 경로는 주지 않으므로 운영 동작이
바뀌지 않고, `tests/test_trace.py` 가 추적 유무로 판정 바이트가 같은 것을 단언한다.

## 범위에서 뺀 것

어드민 검수 화면 일체(SCRUM-283 FE 소관), 인증·권한, 판정 영속화와 이력 조회, 배포와 ECS
노출, 카프카 왕복(`tests/test_roundtrip_live.py` 가 본다), 이미지 검수, 승급률 집계 화면
(`harness/summary.tsv` 가 이미 소유한다).


## 리뷰 요약 탭 (SCRUM-310)

이 탭이 보여 주려는 것은 요약 품질이 아니라 **거짓을 만들지 않는 장치가 실제로 도는가**다.
화면에서 네 가지가 서로 다르게 그려지는 것이 요점이고, 그 구분이 이 기능에서 가장 틀리기
쉬운 자리다.

| 화면 | 뜻 |
|---|---|
| 단점 n건 | 임계를 넘겨 반복으로 센 단점이 있다 |
| "분석한 후기에서 단점 언급이 없었습니다" | 언급이 **아예 없었다** |
| "단점 언급이 있었으나 반복이라 부르기엔 적습니다" | 있었지만 3건·10% 미달이다 |
| "요약을 만들기에 리뷰가 아직 적습니다" | 분모 미달이라 **모델을 부르지 않았다** |
| "반복이라고 셌는데 문장이 없다" (주황 점선) | 코드가 센 숫자는 있고 산문만 없다 |

`demo/summary_view.py` 가 **별 모듈**인 이유: `demo/view.py` 는 검수 5단계 전용이고
`CANONICAL_STAGES`·`ExitPoint` 8종·`_SKIP_REASON_LABELS` 가 검수 어휘로 고정이다. 거기
끼우면 요약 단계가 전부 "도달하지 않음"으로 그려진다.

**환율을 다시 적지 않는다.** `demo/view.KRW_PER_USD` 를 import 하고 테스트가 그것을
단언한다 — 두 숫자가 갈라지면 콘솔이 보여 주는 비용으로 손익분기를 이야기할 수 없다.

### 모드가 셋이다 — 재생 / 모의 / 라이브

검수 탭과 같은 셋이다. **앞 판은 요약 탭에만 `mock` 이 없었고** 키가 없으면 라이브가
내려가므로, 요약 기능에서는 사람이 자기 리뷰를 타이핑해 결과를 보는 일이 아예 불가능했다 --
적어 둔 시나리오 9개만 돌 수 있었다. 발표의 절반이 그 일이다.

`demo/summary_mock.py` 가 그 대역이고 **모델이 아니다.** 키워드 표로 답하는 결정론적
대역이며, 인용은 반드시 본문에서 떼어 오고(꾸미면 증거 검증이 그 항목을 버린다) 집계표 밖의
항목을 올리지 않는다(올리면 출력 게이트가 버린다). 표에 안 걸린 항목은 "없다"가 아니라
**"표에 없다"**는 뜻이고 화면이 그 한계를 함께 띄운다.

### 시나리오 아홉 개가 탈출 지점 전건을 덮는다

`summary-ok` / `summary-adversarial` / `summary-not-enough` / `summary-no-negatives` /
`summary-narration-missing` / `summary-evidence-dropped` / `summary-segment` /
`summary-llm-disabled` / `summary-failed`.

`summary-adversarial` 이 한 화면에 방어 넷을 모아 둔다 — 주입 제외, 중복 접기, 연락처
레닥션, 가짜 머리줄 귀속 인용 탈락.

### 카세트 키가 (툴 이름, 순번)이다

검수 카세트는 `(툴 이름, 관점)` 키를 쓴다. 요약에는 쓸 수 없다 — `report_findings` 가 아닌
툴은 `(name, None)` 이 되므로 추출 배치가 두 번 있으면 **같은 응답이 두 번 흘러 들어간다.**
요약은 배치 수가 리뷰 수에 따라 변하고 서술도 스코프마다 한 번씩이라 그 충돌이 정상 경로에서
난다. 그래서 `demo/replay.py` 에 `SequencedReplayClient` 를 두고 키를
**(툴 이름, 그 툴의 호출 순번)** 으로 잡았다.

### 분모를 사람 입력에서 그대로 믿지 않는다

모의·라이브가 쓰는 요청 조립이 레포 1순위 불변식("통과와 미검사를 섞지 않는다")을 깼던
자리다. 앞 판은 사람이 자유 입력하는 `분모`(기본 20)를 `totalVisibleReviews` 와
`basisReviewCount` 양쪽에 박고 `unextractedReviewCount=0` 을 하드코딩했다. 실제 투입 리뷰는
textarea 줄 수(기본 5)다. 그래서 **콘솔 출고 기본 상태에서** 화면이 "분석 20건 / 못 읽은
리뷰 0건"을 그렸고, `summary_min_reviews=10` 임계도 그 조작된 분모가 통과시켜 서술 호출까지
났다. 긍정 리뷰 3건이면 `NO_NEGATIVE_MENTIONS_FOUND` — 17건을 한 글자도 읽지 않고 "단점
언급을 찾지 못했다"로 내보낸다.

지금은 **못 읽은 리뷰 수를 그 차이로 채운다**: `unextractedReviewCount = 분모 - 투입 리뷰`.
분모가 투입 리뷰보다 작으면 조립하지 않고 거부한다(음수가 된다). 분모를 입력으로 남겨 두는
것 자체는 쓸모가 있다 — "전체 1,000건 중 신규 12건만 추출됐다"를 사람이 재현해 볼 수 있어야
한다. 서비스는 처음부터 멀쩡했다(정직한 숫자를 주면 `PARTIALLY_UNEXTRACTED` 가 난다). 거짓말은
데모의 요청 조립 한 자리였다.

### 라이브 모드

`AECHAK_AI_ANTHROPIC_API_KEY` 가 있을 때만 켜진다. 리뷰를 한 줄에 한 건씩 `"5|본문"` 모양으로
넣는다. 별점을 빼면 5점이다. 기본은 언제나 재생이다 — 발표 중에 사람이 실수로 유료 경로를
밟지 않는 쪽이 기본이어야 한다.

## 셀러 폼 초안 탭 (SCRUM-311)

**이 탭의 존재 이유는 두 방식을 나란히 놓는 것이다.** 사람이 아직 (가) 상품명+카테고리만 /
(나) 사진 한 장 중 무엇을 켤지 고르지 못했고, 고르려면 비용·지연·초안을 같은 입력에서
나란히 봐야 한다. 시나리오 하나를 두 변형으로 돌려 비교표를 찍는다.

### 왜 이 비교가 공정한가

두 방식은 **별 코드 경로가 아니다.** 같은 프롬프트·툴·모델·접두부를 쓰고 **이미지 블록
하나의 유무만 다르다.** 이미지는 messages 에 들어가 접두부 캐시를 깨지 않으므로 두 변형이
같은 캐시 엔트리를 공유한다 — 변수가 하나다. 화면이 그 사실과 **"한 건의 차이는 결론이
아니다"**(층별 한계 이득은 `harness/run_draft.py` 가 잰다)를 함께 적는다.

### 화면이 가르는 것 — 빈 필드의 사유 넷

검수 탭이 통과와 미검사를 가르고 요약 탭이 "없다"와 "셌는데 문장이 없다"를 가르는 것처럼,
초안 탭은 **넷**을 가른다. 색 어휘를 따로 쓰고 테스트가 그 CSS 규칙의 존재를 단언한다.

| 사유 | 화면 |
|---|---|
| 설계상 채우지 않는다 (가격·재고·이미지 키) | 회색. "못 했다"가 아니라 "안 한다" |
| 품목을 몰라 시도하지 않았다 | 노란색 |
| 가드가 걸러 비웠다 (규칙/금지성분/효능/옵션/근거/길이) | 노란색 + 겹 이름 |
| **호출이 죽어서 못 봤다** | **강조 배경.** "제안할 것이 없었다"로 그리면 거짓이다 |
| 셀러가 고친 값을 그대로 둔다 | 파란색 |

### 0원으로 끝난 길이 서로 다른 라벨이다

상품명 0단 룰 차단 / **상품명 효능 단정 차단** / 품목 미식별 / 기능 꺼짐 / **사진 거부**가
한 라벨로 뭉개지지 않는다. 효능 차단은 뒤늦게 더했다 -- 0단이 `rules.screen` 만 보고
`claims.screen` 은 **모델 출력에만** 걸려 있어서, '관절염 치료 목줄' 에 모델이 1회 불리고
완성 초안이 나갔다(셀러가 저장하면 등록 검수가 상품명으로 막는다). 특히
사진 거부는 **호출 전에** 끝난 것이라 호출 실패와 뜻이 정반대다 — 전자는 셀러센터가 사진을
줄여 다시 보내면 되고 후자는 다시 시도해야 한다. (처음 구현에서 둘이 같은 라벨로 그려졌고
시나리오를 돌려 보고 찾았다.)

**효능 차단은 출력 가드와 같은 사전을 쓰지 않는다.** 처음에 같은 사전을 걸었고, 그래서
정상 상품명 16건 중 8건이 막혔다('3일 배송 보장 고양이 모래'·'후기 많은 인기 하네스'·
'치료실 전용 매트'·'염증 걱정되는 아이용 순한 패드' …). 이름 경로에서 과탐의 비용은 '필드
하나 비움'이 아니라 **'초안을 아예 안 줌 + 셀러를 꾸짖는 안내문'** 이고, 안내문이 오진하면서
'질병·치료·기간 약속 표현을 빼라'고 지시하므로 셀러는 무엇을 고쳐야 하는지 알 수 없다.
지금 이름은 `claims.screen_name()` 이 보고 **모호하지 않은 어휘와 '질병명 AND 결과 동사'
공기**만 막는다. 안내문도 층 이름이 아니라 **적중한 글자**를 보여 준다(`'관절염, 치료'`).

### 사진은 합성 헤더다

`imagemeta` 가 **헤더만** 읽고 픽셀을 디코드하지 않으므로(그래서 Pillow 가 필요 없다),
재생 시나리오는 서명 + IHDR + 패딩으로 만든 PNG 로 치수·토큰 예산·저품질 판정 경로를 전부
실제로 태운다. **그것으로 보여 줄 수 없는 것**을 적어 둔다: 모델이 실제 사진을 읽는 능력.
그것은 키가 들어온 뒤 하네스의 실제 픽스처로만 측정된다. 여기서 보여 주는 것은 **분기와
비용 구조**다.

### 시나리오 열넷이 탈출 지점 전건을 덮는다

품목 확정 / 품목 미식별(0원) / 상품명 차단(0원) / **상품명 효능 단정(0원)** / 효능 단정 /
금지 성분 / 옵션 불변식 /
근거 불일치 / 분류 불일치 / 모델이 고르지 못함 / 호출 실패 / 오사진 / 잠근 필드 / 사진 거부.
**적어 둔 경로로 돌지 않으면 그림을 내보내지 않는다** — 사이드바에 시나리오 설명과
`expected_exit` 가 떠 있으므로 다른 경로를 그리면 화면이 자기를 부정한다.

### 라이브 모드

`AECHAK_AI_ANTHROPIC_API_KEY` 가 있을 때만 켜진다. 상품명과 (선택) 카테고리 id 를 넣고
"사진 변형도 같이 돌린다"를 켜면 두 열이 나온다. 라이브의 사진도 합성 헤더라 **비용 구조와
분기만** 보여 준다. 기본은 언제나 재생이다.

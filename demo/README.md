# 데모 콘솔 (SCRUM-290)

검수 한 건이 N0 규칙부터 N5 확정까지 **어디를 지나는지** 눈으로 따라가는 화면이다.
AI 서버가 자기 파이프라인을 설명하는 개발·데모용이고, 어드민 검수 화면은 범위가 아니다
(그쪽은 SCRUM-283, FE가 맡는다).

```bash
uv run python -m demo              # http://127.0.0.1:8100
uv run uvicorn demo.app:app --port 8100
```

기본 모드는 **재생**이다. 키가 없어도 돌고 비용이 0이다.

## 왜 별 프로세스인가

운영 앱(`app/main.py`)에 라우트를 붙이지 않는다. 근거 셋이다.

1. `app/main.py` 가 "HTTP로는 헬스체크만 공개한다. 공개 ALB 뒤에 있으므로 관리용 경로를 열어
   두면 이름이 internal이어도 외부에서 닿는다"고 명시하고 `docs_url` 까지 끈 상태다. 콘솔을
   거기 붙이면 **인증 없는 콘솔이 공개 ALB에 선다.**
2. Dockerfile이 `COPY app` 과 `COPY prompts` 만 한다. 그래서 `demo/` 는 **운영 이미지에 애초에
   들어가지 않는다.** `harness/` 가 이미 같은 규칙으로 밖에 있다.
3. **새 의존성이 0이다.** FastAPI와 uvicorn은 이미 main 의존성이라 `uv.lock` 이 그대로다.
   Streamlit을 쓰면 pandas·pyarrow·altair가 따라오고, `[project.dependencies]` 에 넣는 순간
   운영 이미지에 실린다. 비기본 그룹으로 빼도 락파일 전체가 다시 해석된다.

`tests/test_demo.py` 의 `test_운영_...` 셋이 이 배치를 지킨다 — Dockerfile이 `demo` 를 담지
않는 것, 운영 의존성 목록이 그대로인 것, 운영 앱에 콘솔 경로가 없는 것.

## 모드 넷

| 모드 | 모델 호출 | 쓰는 자리 |
|---|---|---|
| **재생**(기본) | 없음. 손으로 쓴 카세트 | 탈출 지점 다섯을 보여 주는 발표 경로 |
| **모의** | 없음. 키워드 표로 답하는 대역 | 사람이 자기 문장을 넣어 보는 자리. 판정은 모델 판단이 아니다 |
| **라이브** | 실제 호출. 돈이 든다 | 키가 있을 때만 켜진다 |
| **저장된 판정** | 없음. 판정 JSON을 다시 그린다 | 기록된 판정의 모양을 되살릴 때 |

### 재생이 모델 **경계**에서 되돌리는 이유

판정 JSON 하나를 다시 그리는 얕은 재생으로는 보여 줘야 하는 것의 절반이 나오지 않는다.
선별 사유·비평 결정·단계 라벨·실패 상세가 판정 계약에 없기 때문이다. 그래서 `call_tool` 만
구현한 `ReplayLlmClient` 를 끼운다. 그러면 **실제 파이프라인이 그대로 돌아** 추적 전체가
생기고, 결정론적이며 비용이 0이다. 이 이음매는 이미 열려 있었다 — 파이프라인은 `llm` 을
덕 타이핑으로 `call_tool`/`aclose` 만 부른다. **운영 코드는 한 줄도 바꾸지 않았다.**

카세트 키는 호출 순서가 아니라 **(툴 이름, 관점)** 이다. 순서로 두면 분기가 바뀔 때마다
조용히 어긋난 응답이 흘러 들어간다. 없는 키는 `CassetteMiss` 로 터뜨린다 — 선별과 비평이
실패를 각각 승급과 유지로 접기 때문에, 빠진 카세트를 조용히 실패로 돌리면 콘솔이 거짓
단계를 그린다.

### 모의는 모델이 아니다

`demo/mock.py` 는 키워드 표로 답하는 결정론적 대역이고 토큰·비용은 글자 수에서 뽑은
추정값이다. 인용은 반드시 본문에서 떼어 온다 — 꾸며 쓰면 인용 검증이 그 판정을 버려
전건이 `EVIDENCE_UNVERIFIED` 로 떨어진다.

**판정이 추정값이라는 것을 결과 패널 머리줄이 말한다.** 모의 모드에서는 `모의 판정` 배지와
"이 판정은 키워드 표가 낸 것이다. 모델 판단이 아니다"가 함께 뜨고, 백엔드 게이트 배지는
중립색으로 내려간다. 종전에는 모의임을 알리는 표시가 원장 밑의 "토큰과 비용은 추정값이다"
한 줄뿐이라 **판정**이 추정이라는 경고가 없었고, 그 상태에서 사람이 자기 문장을 넣으면
결과가 "이 시스템은 이것을 이렇게 판정한다"로 읽혔다.

**모의 선별은 표에 안 걸리면 `NEEDS_REVIEW` 다.** 실제 프롬프트의 "확신이 서지 않으면
NEEDS_REVIEW" 와 같은 방향이다. 대역은 깨끗함을 증명할 수 없고, 표에 안 걸린다는 것은
"표에 없다"는 뜻일 뿐이다. `CLEAR` 는 깨끗하다고 적어 둔 표본 문구
(`mock.CLEAR_SAMPLE_MARKERS`)에만 낸다 — 종전에는 반대 방향이어서 정책의 위반 예시 그대로를
넣은 리뷰가 선별 통과 + 백엔드 게이트 통과로 떨어졌다.

### 키가 들어오면

`harness/run.py` 에 `--record` 를 더해 각 호출의 kwargs와 `LlmResult` 를 덤프하면 손으로 쓴
카세트를 실측 카세트로 갈아탈 수 있다. 하네스가 이미 모드별로 전 케이스를 돌리므로 덤프
지점은 `_run_pipeline_mode` 한 곳이다.

## 화면이 가르는 것

**통과(CLEAR)와 미검사(UNCHECKED)를 색과 라벨 양쪽으로 가른다.** 이것이 수용 기준이고
프로젝트 전체의 불변식이다. 그래서 단계 줄이 축을 둘 든다.

- `status` — 돌았는지 / 건너뛰었는지 / 걸렸는지 / 도달하지 않았는지
- `outcome` — 통과 / 미검사 / 위반

둘을 한 값으로 합치면 "아무도 안 봤다"가 "문제 없다"와 같은 색으로 그려진다.

탈출 지점 여섯(+둘)은 `ContentVerdict` **하나만으로** 갈린다. 그래서 추적이 없는 얕은
재생에서도 배지가 나온다.

| 탈출 | 판별 |
|---|---|
| 규칙 차단 | `FLAG` + 원장이 빔 + RULE 행이 VIOLATION |
| 선별 통과 | TRIAGE 행이 `CLEAR` |
| 모델 위반 없음 | `PASS` + 모델 관점 **전부**가 실제로 판정 |
| 부분 미검사 통과 | `PASS` + 모델 관점 가운데 `UNCHECKED` 가 하나라도 있음 |
| 비평 뒤집힘 | `criticOverturned=true` |
| 확정 위반 | `FLAG` + 모델 호출이 있음 |
| (판정 실패) | `FAILED` |
| (stub 모드) | `FAILED` + `LLM_DISABLED` |

**부분 미검사 통과를 따로 둔 이유.** 집계가 통과를 내는 조건은 "**한** 관점이라도 판정했고
위반이 없다"다. 그래서 의료·효능 주장을 보는 유일한 관점이 인용 검증 실패나 레이트 리밋으로
죽어도 판정은 `PASS` 다. 그 둘을 한 배지로 합치면 머리줄이 "관점이 실제로 읽고 위반을 찾지
못했다. 이 통과는 미검사가 아니다"로 사실의 반대를 단정한다. 이 탈출의 설명문은 고정 문장이
아니라 관점 행에서 센 수치다 — "쏜 관점 2건 중 1건만 읽었다".

**재생은 환경변수를 한 칸도 읽지 않는다.** `Scenario` 가 파이프라인 모양 전부
(`enable_triage`·`perspective_fanout`·`enable_escalation`·`enable_notice`·모델 ID 넷)를 들고
`Scenario.settings()` 가 리터럴에서 조립한다. 그리고 `_run` 이 끝에서 실제 탈출 지점을
`expected_exit` 와 맞춰 보고 어긋나면 화면을 그리지 않고 400을 돌려준다 — 종전에는
셸에 `AECHAK_AI_PERSPECTIVE_FANOUT=false` 가 있으면 네 시나리오가 카세트 미스로 죽고,
비평·수정문구를 끄면 `critic-overturn` 이 오류 없이 "확정 위반"으로 그려졌다(사이드바에는
`expected_exit=CRITIC_OVERTURNED` 가 그대로 떠 있는 채로).

**백엔드 게이트 배지**는 별 축이다. 백엔드 `InspectionFacade.modelVerified()` 를 그대로 옮긴
술어로, 이 통과를 관리자 확인 없이 반영할 수 있는지 답한다. 그 거울은 이 레포에
**하나뿐이다**(`view.backend_accepts`) — `tests/conftest.py` 가 그것을 import 한다. 사본을
둘 두고 "둘이 같은 답을 내는지" 보는 테스트는 항진명제였다(정본이 바뀌어도 둘은 서로 같다).
정본과의 어긋남은 계약 표본마다 게이트 통과 여부를 적은 표가 잡는다. 통과가 아닌 판정에는 적용되지
않는다(보류와 실패는 어차피 사람이 본다).

저장된 판정에서 `content-verdict-triage.json` 을 고르면 그 배지가 **불통과**로 뜬다.
백엔드가 소유한 그 표본이 모델 관점 행 없이 `[RULE/CLEAR, TRIAGE/CLEAR]` 로만 적혀 있어
생산자보다 뒤처져 있기 때문이다. 자세한 것은 `tests/contract/README.md` 에 있다.

## 추적은 계약 밖이다

콘솔이 보여 주는 "왜"는 `ContentVerdict` 에 없다. 그 계약은 백엔드 message 모듈과 1:1이라
필드를 더하면 백엔드가 **에러 없이** 모르는 필드를 버린다. 그래서 `app/inspection/trace.py` 의
인프로세스 객체로 모은다.

**추적기를 주지 않으면 아무 일도 일어나지 않는다.** 카프카 경로는 주지 않으므로 운영 동작이
바뀌지 않고, `tests/test_trace.py` 가 추적 유무로 판정 바이트가 같은 것을 단언한다.

## 범위에서 뺀 것

어드민 검수 화면 일체(SCRUM-283 FE 소관), 인증·권한, 판정 영속화와 이력 조회, 배포와 ECS
노출, 카프카 왕복(`tests/test_roundtrip_live.py` 가 본다), 이미지 검수, 승급률 집계 화면
(`harness/summary.tsv` 가 이미 소유한다).

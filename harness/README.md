# 측정 하네스

러너가 셋이다.

- `python -m harness.run` — 선별 계층(아래 전부)
- `python -m harness.run_summary` — 리뷰 요약(SCRUM-310). **키 없이도 리포트를 찍는다**
- `python -m harness.run_draft` — 셀러 폼 초안(SCRUM-311). **입력 방식 결정이 여기 달려 있다**

## 셀러 폼 초안 러너 (SCRUM-311)

```bash
uv run python -m harness.run_draft                         # 키 없이 도는 리포트 전부 (종료 0)
uv run python -m harness.run_draft --count-tokens          # 접두부 토큰 실측. **키가 필요하다**
uv run python -m harness.run_draft --count-image-tokens    # 이미지 토큰 치환. **키가 필요하다**
uv run python -m harness.run_draft --mode a --repeat 3 --yes
```

**선결 조건을 못 갖춘 호출은 종료 코드 2 이고, 빠진 것을 전부 한 번에 말한다.** 앞 판은
순서가 (1) `lexicon-only` 면 return (2) 키 없으면 return (3) 그 다음에야 플래그·픽스처
검사였다. 그래서 둘이 조용히 거짓이었다 — 기본 모드에서 `--count-tokens` 를 주면 플래그가
**아예 읽히지 않고** 종료 코드 0 이었고, `--mode b` 는 픽스처와 키가 둘 다 없는데 사람은
"키가 없다" 만 들었다(`--compare-from /nope` 도 종료 코드 0 으로 조용히 끝났다).

산출물은 `harness/out/draft-<tag>-<stamp>/{raw.jsonl,summary.tsv}` 다. 태그에 모드가 들어가고
같은 초에 두 번 돌면 `-2` 접미가 붙는다. `raw.jsonl` 은 0줄이라도 쓴다.

**입력 방식이 아직 미결이다** — (가) 상품명+카테고리만 / (나) 사진 한 장. 이 러너가 그
결정의 숫자를 낸다. 모드 다섯:

| 모드 | 무엇 | 비용 |
|---|---|---|
| `lexicon-only` | 0단 어휘 게이트만. 모델 0회 | **0원. 키도 필요 없다** |
| `a` | 이름 + 카테고리(주어진 대로) | (가) |
| `a-blind` | 이름만. 카테고리를 숨긴다 | 카테고리의 한계 이득 대조군 |
| `b` | `a` + 이미지 1장(base64) | (나) |
| `gated` | 어휘 게이트가 확정하지 못했을 때만 이미지 | 조건부 멀티모달(제3안) |

### 왜 이 비교가 공정한가

(가)와 (나)는 **별 코드 경로가 아니다.** 같은 프롬프트·툴·모델·접두부를 쓰고 **이미지 블록
하나의 유무만 다르다.** 이미지는 messages 에 들어가 tools+system 접두부를 깨지 않으므로 두
변형이 같은 캐시 엔트리를 공유한다 — **변수가 하나다.** 즉 (가)는 별 기능이 아니라 (나)의
축퇴이고 `imageUsability = NO_IMAGE_SENT` 로 표현된다.

### 키 없이 뽑는 숫자 — 값비싼 것부터

1. **`lexicon-only` 의 층별 리프 정확도.** 0원 기준선이고 (가)안의 핵심 주장이 실제 상품명
   분포에서 성립하는지다. **현재 케이스 세트: 전체 49%(34/69), EXPLICIT 100%(28/28),
   AMBIGUOUS 16%(3/19), OPAQUE 14%(3/22).** 읽는 법 — 0원 게이트가 품목어가 드러난 이름은
   **전건 맞히고** 나머지는 거의 못 맞힌다. 그래서 모델의 일은 정확히 AMBIGUOUS + OPAQUE
   두 층이고, 모델이 거기서 0단을 넘기지 못하면 그 호출은 비용만 더한다(기계적 중단 규칙).
2. **사진이 모델에 실제로 닿는 건수 = 이미지 이득의 천장.** `OPAQUE` 층 비중(22/75)이
   아니다 — 그 층의 상당수가 카테고리 없이 `ITEM_UNIDENTIFIED` 로 0원 종료해 **사진이
   모델에 실리지 않는다.** 실제값은 b 모드 22건(채점 20) / gated 15건(채점 15)이고, 앞 판의
   "OPAQUE 19/72(26%)" 는 약 3배 과대였다.
3. **모드별 계획표.** 모델 호출 건수·사진 도달 건수·채점 분모·추정 비용이 네 모드에서
   갈려 찍힌다. 앞 판은 네 모드의 리포트가 산출물 경로 한 줄만 빼고 **바이트 동일**했고,
   즉 이 티켓의 핵심 산출물인 비교표가 한 줄도 생산되지 않았다. 정확도만 키를 요구한다.
4. 게이트 등급 x 카테고리 교차표와 **모델 0회 건수**(0원 분기 셋: 0단 룰 차단 / **상품명
   효능 단정 차단** / 품목 미식별).
5. **사전 미적중 목록.** 2층 수기 동의어를 추측으로 채우지 말고 이 목록에서 받는다.
6. 가드 겹별 작동. **정책 효능 위반 예시 8건 중 `rules.screen` 이 잡는 것 0건 / 효능 사전이
   8건** — 그 0 이 `app/seller_draft/claims.py` 를 새로 만든 이유다. 그 사전은 이제 모델
   출력만 보지 않고 **상품명 0단에도 걸린다**(`NAME_CLAIM_BLOCKED`).
6. 봉투 조립 검증과 접두부 글자 수(토큰 수가 아니다).
7. 비용 추정. `--yes` 없이는 추정만 찍고 멈춘다.

측정 전 자기검사가 **여덟 가지**를 보고 하나라도 어긋나면 종료 코드 1이다. 그 가운데 둘이
특히 중요하다 — 층 라벨(`name_reveals`)이 실제 `catalog.resolve()` 결과와 같은가(라벨은
사람 직관이고 게이트는 코드다. 어긋나면 **모든 층별 숫자가 거짓이다**), 그리고 리프 표가
커밋된 시드 사본과 같은가.

### 비용 전제 — 전부 추정이고 실측이 아니다

Haiku 4.5 기준: 텍스트 4,590uUSD(**6.43원**) / +896 사방 이미지 5,614uUSD(**7.86원, +22%**) /
품목 미식별 **0원**. 이미지 증분 비율과 일 상한은 **상수로 적지 않고 비용표에서 파생시키고
테스트가 그 파생을 고정한다.**

**출력 토큰이 이미지보다 큰 레버다.** 출력 300 -> 900 증분이 896 이미지 전체의 약 3배다 —
"이미지를 넣을 것인가"는 비용 문제로서는 두 번째 레버이고, 첫째는 설명 길이 상한이다.

접두부 캐시는 요약과 같은 이유로 **기본 모델에서 쓰지 못한다**(Haiku 하한 4,096토큰).
하한 미달이 실패가 아니라 근거이고(`required=False`), Sonnet 으로 뒤집으면 `required=True`
로 바뀐다. 대상은 **system + 고정 tool 둘 다**다 — tools 가 접두부에 함께 캐시되므로
system 만 세면 둘 중 어느 것도 재지 않는 셈이다.

### 이미지 픽스처는 커밋하지 않는다 — 그래서 자기검사가 **그림 내용**을 본다

50 케이스 x 5 등급 JPEG 이 레포를 수십 MB 불린다. `harness/draft_images/` 는 gitignore 고
`harness/make_draft_images.sh` 만 커밋한다.

gitignore 라 **안을 감사할 사람이 없다.** 그래서 자기검사가 유일성을 본다. 그 검사가 두 번
뚫렸다 — 처음에는 **치수만** 봤고(같은 사진 한 장을 전건에 복사하면 통과), 그 다음에는
**파일 전체 해시**였다(`synthetic_png` 가 패딩을 `tEXt` 청크에 담으므로 같은 치수의 합성
PNG 는 `IHDR`·`IDAT` 이 전부 같고 주석만 다르다. 파일 뒤에 `\x00` 을 붙이는 것도 같은 우회다).
지금은 `harness/imagecontent.py` 가 **메타데이터를 뺀 그림 내용**을 해시하고(PNG `IHDR`+`IDAT`,
JPEG `SOFn`+스캔 데이터, WebP `VP8*`) **등급 전체**를 본다 — 앞 판은 896 안에만 있었다.

**못 막는 것:** 같은 사진을 다시 인코딩한 파일은 내용 해시가 갈린다. 그것까지 막으려면 픽셀을
풀어 지각 해시를 재야 하고 그것이 Pillow 다. 여기서 막는 것은 "한 장을 복사해 깔았다"이고,
`.jpg` 안에 PNG 가 들어 있으면 자기검사가 그 사실을 `[주의]` 줄로 말한다(차단은 아니다 —
하네스가 매직 바이트로 읽은 타입으로 보내므로 동작은 한다). 없으면 `b`·`gated` 모드를 **건너뛰고 이유를
적고 종료 코드 0** 이다 — 조용히 비어 있는 것이 더 나쁘다. 그래서 **"키만 들어오면 바로
돈다"는 약속이 이미지 모드에는 해당되지 않는다**: 사진 준비가 선결이고 그 품질이 측정
결과를 좌우한다.

### 키가 들어오면 돌리는 순서

```bash
export AECHAK_AI_ANTHROPIC_API_KEY=sk-ant-...

uv run python -m harness.run_draft --count-tokens                       # 1) 접두부 토큰
uv run python -m harness.run_draft --count-image-tokens                 # 2) 이미지 토큰
uv run python -m harness.run_draft --mode lexicon-only                  # 3) 0원 기준선
uv run python -m harness.run_draft --mode a --repeat 3 --yes
uv run python -m harness.run_draft --mode a-blind --repeat 3 --yes
uv run python -m harness.run_draft --mode b --repeat 3 --yes
uv run python -m harness.run_draft --mode gated --repeat 3 --yes
uv run python -m harness.run_draft --mode a --model sonnet --repeat 3 --yes
uv run python -m harness.run_draft --mode b --variant 640 --yes
```

산출물은 `harness/out/draft-<모드>-<모델>-<해상도>-<타임스탬프>/{raw.jsonl,summary.tsv}` 다.
층별 한계 이득은 앞선 모드의 `raw.jsonl` 을 `--compare-from` 으로 넘겨 계산한다.

### 그 표를 사람이 어떻게 읽는가

**0순위 — 먼저 `층별 사진 보유` 줄을 본다.** 사진 픽스처가 걸린 케이스는 층별로 치우쳐
있고(현재 AMBIGUOUS 8/19, EXPLICIT 5/34, OPAQUE 16/19), 사진이 없는 건은 `a` 와 `b` 가
**완전히 같은 입력**을 받는다. 그 층의 delta 는 이미지 효과가 아니라 반복 불일치 잡음이다
(결정성 레버가 API 층에 하나도 없다). 그래서 리포트가 두 줄을 나란히 찍는다.

| 줄 | 분모 | 무엇을 말하는가 |
|---|---|---|
| `한계 이득` | 층 전체 | 운영에서 그 모드를 켰을 때의 **평균 효과**(희석됨) |
| `한계 이득(사진 보유만)` | 사진 있는 케이스 | **이미지가 실제로 하는 일** |

둘이 크게 다르면 그 차이가 희석의 크기다. **`ALWAYS` 를 켜는 판단은 아래 줄로 한다.**

그 다음 순서대로.

- 이미지 한계 이득이 **`OPAQUE` 층에서만** 크고 다른 층에서 0 에 가까우면 → **`gated`**.
  그때 이미지 비용은 `OPAQUE` 층 비중만큼만 든다.
- 세 층 전부에서 작으면 → **`OFF`(가).** 증분 1.43원을 아끼는 것이 아니라 **운영 표면과
  사진 품질 의존성을 아예 들이지 않는 것**이 이득이다.
- 세 층 전부에서 크면 → **`ALWAYS`(나).** 비용 증분이 +22% 이므로 정확도 이득이 그만큼이면
  정당하다.
- **오사진 안전율이 낮으면(`WRONG` 사진에서 `MISMATCHES_NAME` 을 못 내고 초안을 써 버리면)
  정확도 숫자와 무관하게 이미지를 켜지 않는다.** 그것은 비용 문제가 아니라 거짓 문제다.
  분모가 `WRONG_PHOTO_MIN_CASES`(6)에 미달하면 러너가 그 줄을 **"판정 불가"로 찍는다** —
  1건짜리 숫자로 출시 게이트를 통과시키지 않는다. **분모는 WRONG 전수가 아니라 모델에 닿는
  건수다**(b=8 / gated=6). 전수를 세던 판에서는 실제 측정 분모가 5건인데 "최소 6건 충족"
  이라고 찍혔고, 그 집합으로는 게이트가 영구히 판정 불가였다 — OPAQUE + 카테고리 없음인
  건은 모델을 0회 부른다. 그래서 OPAQUE 층에 **상위 카테고리를 준** 오사진 셋을 더했다. 종류별로 갈라 본다(`OTHER_ITEM` /
  `OTHER_SPECIES` / `NO_PRODUCT`): **같은 품목 다른 종**이 반려동물 커머스에서 더 흔하고
  더 위험하다.

### 이 하네스가 **판정할 수 없는 것** — 읽기 전에 알아야 한다

자동 채점되는 축은 **리프 정확도와 옵션 그룹명 적중** 둘뿐이다. 옵션 쪽 분모는 **정답이
있는 케이스 전수**이고, 모델이 옵션을 하나도 내지 않은 건은 "미측정"으로 함께 찍힌다 --
앞 판은 그 건을 분모에서 빼서 53건 중 10건만 옵션을 내고 그 10건이 맞으면 `10/10(100%)`
으로 찍혔고 43건이 아무것도 못 냈다는 사실이 어디에도 안 적혔다. 그런데 이미지를 넣어서
가장 좋아질 것은 리프 50 중 하나를 맞히는 일이 아니라 **설명과 속성의 구체성**이고,
그 축에 자동 채점이 없다.

- `필드 사유` 의 `description:FILLED` 는 **채웠는가**만 말하고 쓸모 있는가는 말하지 않는다.
- 설명 품질 사람 채점은 하지 않았고, **채점자가 설계자 자신이면 편향되는데 그 편향을 막는
  장치도 넣지 않았다.**
- `채택률`(셀러가 초안을 그대로 저장했는가)은 백엔드 `product_drafts` 스냅샷 비교가
  선결이고 이번 범위 밖이다.

그래서 **리프 정확도만으로 `ALWAYS` 를 켜지 마라.** 리프 이득 천장은 사진이 모델에 닿는
22/75건(b 모드, 채점 20건)으로 이미 얇고, 그 축에서 이득이 작게 나와도 설명 쪽에서 클 가능성을 이
하네스는 배제하지 못한다(그 반대도 마찬가지다). `ALWAYS` 를 켜려면 **설명 품질의 사람
채점을 먼저 붙여야 하고, 채점자를 설계자와 분리해야 한다.** 그 전에 고를 수 있는 것은
`OFF` 와 `gated` 둘이다.

**(나) 쪽에 기계적 손익분기를 만들 수 없고, 만든 척하지 않는다.** 틀린 리프 하나의 값
(셀러가 카테고리를 다시 고르는 수고)이 돈으로 환산되지 않는다. 대신 측정 후 파생되는
"이미지로 추가로 맞힌 1건당 비용"과 비용 증분율을 나란히 찍고 **사람이 정한다.** 그 줄은
케이스 집합으로 정규화되고, 추가로 맞힌 건 가운데 **사진을 받지도 않은 케이스**가 있으면
몇 건인지 함께 찍는다 — 그것은 잡음 역전이고 이미지 공로가 아니다.

### 비용 줄은 전부 단가 정본에서 파생된다

`_DRAFT_TOKEN_ASSUMPTIONS` 만 상수이고 microUSD 는 `app/llm/client.cost_micro_usd()` 가
계산한다. 전에는 손계산한 microUSD 를 표에 적어 뒀고, 값은 맞았지만 연결이 없어서
`_PRICING` 을 고치는 날(그 주석이 "모델 확정 시 공식 단가로 재확인한다"고 예고한다)
모든 비용 줄과 일 예산 상한이 **조용히 과거 값으로 남고 테스트는 전부 초록**이었다.
테스트가 이제 단가를 두 배로 올렸을 때 표가 따라 움직이는 것을 단언한다.

### 효능 사전 커버리지는 보류 집합으로만 읽는다 — 그리고 지금은 **비순환 숫자가 없다**

`정책 효능 위반 예시 8건 중 claims 사전이 잡는 것 8건` 은 **커버리지가 아니다.** 분모가
사전의 출처와 같고 같은 목록이 프롬프트에도 들어가므로 순환이며, 미지의 표현에 대해
아무것도 말하지 않는다.

보류 집합이 **둘**이고 **둘 다 순환이 됐다.**

| 줄 | 숫자 | 처음 잰 값 | 왜 순환인가 |
|---|---|---|---|
| `효능 사전 보류 집합` | 8/8 | 0/8 | 그 목록을 보고 질병명·완치 동사·기간 단정·후기 인용 층을 더했다 |
| `두 번째 보류 집합` | 18/18 | 5/18 | 그 목록을 보고 '증상 명사 + 낫게 만드는 동사' 공기 층을 더했다 |

두 번째 집합이 드러낸 미탐의 축은 하나였다 — 사전이 전부 **단일 어휘**라 '구취가 사라져요'·
'설사가 멈춥니다'·'기력이 돌아옵니다' 같은 **구조**를 하나도 보지 못했다. 리터럴을 베끼지
않고 그 구조를 세는 층을 더했지만, 목록을 보면서 썼으므로 숫자는 순환이다.

**세 번째 집합은 실제 셀러 문구에서 받아야 한다.** 내가 지어낸 문장으로 만든 집합은 규칙을
쓴 사람이 같아서 증거가 약하다. 리포트가 숫자 대신 그 사실을 적는다.

### 이름 0단과 출력 가드는 **다른 사전**을 본다

같은 사전을 두 경로에 걸었던 것이 결함이었다. `claims.py` 머리글이 과탐 방향을 고른 근거는
"과탐은 필드를 비우게 하고(셀러가 직접 쓴다) 과소탐은 셀러 상품이 차단되게 한다" 이고, 그것은
**출력 가드**의 비용 구조다. 이름 0단(`NAME_CLAIM_BLOCKED`)에서는 과탐의 비용이 '필드 하나
비움'이 아니라 **'초안을 아예 안 줌 + 셀러를 꾸짖는 안내문'** 이라 논증이 거꾸로 선다.

실측: 정상 상품명 16건을 출력 가드 사전으로 재면 8건이 걸린다('3일 배송 보장 고양이 모래'·
'후기 많은 인기 하네스'·'치료실 전용 매트'·'염증 걱정되는 아이용 순한 패드'·'완치 기원
쾌유 카드'·'보장된 내구성 하네스' …). 안내문이 오진하면서 '질병·치료·기간 약속 표현을 빼라'고
지시하므로 셀러는 무엇을 고쳐야 하는지 알 수 없다.

그래서 `claims.screen_name()` 은 둘만 본다 — (가) 모호하지 않은 어휘(`만병통치`·`특효`·
`부작용이 전혀 없`·`모든 ~에게 효과`·`완전해결`·`식약처 인증`·`의약품`), (나) **질병명 AND
결과 동사의 공기**('관절염 치료'·'아토피 완치'). `이름 0단 과탐` 줄이 **0/16** 이다.
느슨한 층은 출력 가드(`claims.screen()`)에 남는다. **이 분모도 내가 쓴 것이라 진짜 과탐률이
아니다** — 숫자를 쓰려면 백엔드의 실제 상품명에서 받아야 한다.

### 옵션 그룹 적중은 분모 전체가 미측정이면 **백분율을 찍지 않는다**

분모를 '정답이 있는 케이스 전수' 로 바꾼 뒤에도 백분율을 그 분모로 계산해, 모델을 한 번도
부르지 않는 `lexicon-only` 리포트에 `0/66(0%)` 이 찍혔다. TSV 컬럼만 보는 사람에게 그것은
'0% 정확도'로 읽힌다 — 통과와 미검사를 섞지 않는다는 불변식을 측정 쪽에서 반쯤 되돌린 모양이다.
지금은 측정 건수가 0 이면 `미측정 66/66` 으로만 적고, 있으면 `24/66 — 측정 24건 중 24
적중(100%) / **미측정 42건**` 처럼 두 숫자를 갈라 찍는다.

## 리뷰 요약 러너 (SCRUM-310)

```bash
uv run python -m harness.run_summary                  # 키 없이 도는 리포트 전부 (종료 0)
uv run python -m harness.run_summary --count-tokens   # 접두부 토큰 실측. **키가 필요하다**
uv run python -m harness.run_summary --repeat 3 --yes # 실측. **키가 필요하다**
```

**키가 필요한 플래그는 키가 없으면 종료 코드 2 다. 모드와 무관하게 그렇다.**

`run_draft` 쪽은 이 판정을 한 번 더 틀렸다 — blocker 가 `args.mode != "lexicon-only"` 에
묶여 있었고 `--mode` 기본값이 `lexicon-only` 라서, **기본 모드에서 `--count-tokens` 와
`--count-image-tokens` 가 다시 조용히 무동작이었다**(바이트 동일한 리포트 + 종료 코드 0).
그 리포트가 사람에게 "`--count-tokens` 가 치환한다"고 권하는 줄을 담고 있었다. 지금은
`needs_key = 모델 모드 or --count-tokens or --count-image-tokens or --yes` 다.

앞 판은 "키가 없으면 리포트를 찍고
return 0" 이 플래그 분기 **위**에 있어서 세 호출의 출력이 산출물 경로 줄만 빼고 글자 그대로
같았다 — 사람은 측정을 요청했는데 받은 것은 같은 리포트 한 장이고, 종료 코드가 0 이라
스크립트도 성공으로 읽었다. 요청한 일을 못 했으면 종료 코드로 말한다.

산출물은 `harness/out/summary-<stamp>/{raw.jsonl,summary.tsv}` 다. **같은 초에 두 번 돌면
`-2` 접미가 붙는다**(앞 판은 `mkdir(exist_ok=True)` 로 조용히 덮었다). `raw.jsonl` 은
0줄이라도 쓴다 — 없으면 읽는 사람이 raw 를 잃었는지 애초에 없었는지 구별할 수 없다.

**키가 없어도 값이 나온다.** 그리고 지금 이 범위에서 가장 값비싼 숫자가 거기서 나온다 --
합성 펫 모집단에 대한 티어·세그먼트 분포다. `NO_PET_INFO` 가 압도적이거나 어느 세그먼트도
최소 8건에 닿지 않으면 **백엔드 펫 스냅샷 티켓을 쓸 가치가 없고, 그 사실을 티켓을 쓰기
전에 알 수 있다.** (현재 케이스 세트: 리뷰의 83%(39/47)가 펫 정보 없음, 세그먼트 0/7 달성.
이 수는 러너가 실제로 찍는 값이다 — 보고에 78%로 옮긴 적이 있는데 그것은 케이스를
더하기 전의 수였고, 러너 출력과 어긋나면 **러너가 맞다.**)

키 없이 찍는 것:

1. 티어·세그먼트 분포 (위)
2. 입력 게이트 통계 — 주입 제외·중복 접기·절단·레닥션 건수
3. **극성 경계 민감도** — 설계안의 넓은 경계(1~2점 PRO / 4~5점 CON 전부 버림)로 두면
   반복 단점이 몇 개 사라지는지. 경계를 되돌리려는 다음 사람이 주석 대신 이 표를 먼저 본다
4. 단점 부재 사유 네 갈래가 케이스 세트에 다 있는지
5. 비용 추정 — **전부 추정이고 실측이 아니다.** `--yes` 없이는 추정만 찍고 멈춘다

측정 전 자기검사가 여섯 가지를 보고 **하나라도 어긋나면 종료 코드 1**이다. 틀린 기대값으로
잰 숫자는 아무것도 말하지 않는다.

비용 전제(Haiku 4.5, 추정): 추출 배치 10건 16,050uUSD(건당 2.25원) / 서술 1회
7,300uUSD(10.22원, **리뷰 수에 무관**). 일 예산 상한은 상수로 적지 않고 그 표에서
파생시키고 테스트가 파생을 고정한다.

접두부 캐시는 **기본 모델에서 쓰지 못한다.** Haiku 4.5 의 최소 캐시 접두부가 4,096토큰이라
`cache_control` 을 붙여도 에러 없이 무시된다. 하한 미달이 실패가 아니라 **근거**이고
(`required=False`), 패딩으로 맞추는 것은 아래 표가 거부한다. Sonnet 으로 뒤집으면
`required=True` 로 바뀌어 `--count-tokens` 가 하한 미달을 종료 코드로 알린다.

# 선별 계층 측정 하네스

선별(Haiku 4.5)을 켤지 말지를 **숫자로** 정하기 위한 러너다. 카프카를 타지 않고
`InspectionPipeline.run()`을 직접 부른다.

이 기능의 가치는 전부 **승급률** 하나에 걸려 있다. 승급률이 손익분기를 넘으면 선별은 비용을
늘리는 기능이다. 그래서 승급률이 1순위 지표이고 중단 규칙도 그 숫자로 적어 둔다.

## 키

환경변수는 `ANTHROPIC_API_KEY`가 **아니라** `AECHAK_AI_ANTHROPIC_API_KEY`다. `Settings`의
`env_prefix`가 `AECHAK_AI_`이기 때문이다. SSM 파라미터 이름도 같다 —
`/aechak/dev/ai/AECHAK_AI_ANTHROPIC_API_KEY`.

키가 없으면 러너가 이유를 적고 **종료 코드 0으로 건너뛴다.**

## 돌리는 순서

```bash
export AECHAK_AI_ANTHROPIC_API_KEY=sk-ant-...

# 1) 토큰 실측. 거의 무료라 맨 먼저 돈다
DOCKER_HOST="unix:///Users/woonkyung/.orbstack/run/docker.sock" \
  uv run python -m harness.run --count-tokens

# 2) 기준선. 선별 없이 Sonnet 2관점 전건
DOCKER_HOST="unix:///Users/woonkyung/.orbstack/run/docker.sock" \
  uv run python -m harness.run --mode baseline --repeat 3 --yes

# 3) 선별 판정만. Sonnet을 부르지 않아 승급률만 싸게 본다
DOCKER_HOST="unix:///Users/woonkyung/.orbstack/run/docker.sock" \
  uv run python -m harness.run --mode triage-only --repeat 3 --yes

# 4) 전체 흐름. net_miss 를 재려면 2)의 산출물 경로를 준다
DOCKER_HOST="unix:///Users/woonkyung/.orbstack/run/docker.sock" \
  uv run python -m harness.run --mode full --repeat 3 --yes \
  --baseline-from harness/out/<2단계의 타임스탬프>
```

`--yes`가 없으면 **예상 비용만 출력하고 멈춘다.** 케이스 50건에 반복 3회면 호출이 수백 건이 된다.
`--only <케이스ID> ...`로 몇 건만 골라 돌릴 수 있다.

산출물은 `harness/out/<타임스탬프>/`에 `raw.jsonl`과 `summary.tsv`로 떨어진다. 그 디렉터리는
`.gitignore`에 있다.

`--repeat` 기본값이 3인 이유는 결정성 레버가 하나도 없기 때문이다. `temperature`를 못 쓰고
Haiku는 `effort`도 못 받는다. 같은 입력의 판정이 흔들리는 폭을 재지 않으면 승급률 측정값
자체를 믿을 수 없다.

## 재는 지표

| 지표 | 정의 |
|---|---|
| **승급률** (1순위) | `NEEDS_REVIEW / 선별을 실제로 탄 건`. PRODUCT와 REVIEW로 나눠 본다 |
| `triage_miss` | 라벨이 `VIOLATING`인데 선별이 `CLEAR`로 내려보낸 건 |
| `net_miss` | 그중 `baseline` 모드에서는 보류가 나왔던 건. **선별 때문에 생긴 누락은 이것뿐이다** |
| 건당 비용 | 선별만 / 선별+Sonnet / baseline, 그리고 본문 길이별 |
| 지연 | 모드별 p50과 p95 |
| 묻지 않고 승급 | 규칙이 적중해 선별을 건너뛴 건. **여기서는 절감이 0이다** |
| 선별 실패율 | 실제로 물은 건 중 호출 실패가 차지하는 비중 |
| 선별 상한 초과 | 사유가 길어 끊긴 호출(`TRUNCATED`). 실패와 따로 센다 — 고칠 방법이 다르다 |
| 반복 불일치 | 같은 케이스의 판정이 반복 간에 갈린 비율 |

승급률 분모는 **규칙이 차단하지 않은 전건**이다. 분모에서 빠지는 것은 둘뿐이다.

1. 규칙이 즉시 차단한 건. 선별을 아예 타지 않는다. 케이스마다 `expect_rule_block`을 달아
   두었고, 러너가 그 플래그를 실제 규칙 결과와 맞춰 보고 어긋나면 측정 전에 멈춘다.
2. 선별이 꺼져 있던 건(`OFF`). baseline 모드가 전부 이쪽이다.

규칙이 **비차단으로** 적중해 선별에 묻지 않고 승급한 건은 분모에 **남는다**(`SKIPPED_RULE_HIT`).
운영은 그 건을 실제로 처리하면서 Sonnet 2회를 그대로 태우므로, 분모에서 빼면 "선별이
아무것도 아끼지 못하는 건"의 비중이 지표에서 구조적으로 사라진다. 그 비중을 보려고
`묻지 않고 승급` 줄을 따로 싣는다.

어느 적중이 선별을 건너뛰게 하는지는 `RuleResult.triage_trumping`이 소유한다. 지시형
문장(비차단 인젝션)은 건너뛰고, advisory 성분 적중은 선별에 **묻는다** — 성분 적중은
"위험하다"가 아니라 "카테고리를 함께 봐야 안다"는 뜻이고, 선별은 성분을 판정하는 것이
아니라 더 볼지만 정한다. 전부 승급시키면 코코넛오일·우유처럼 반려동물 상품에 흔한
성분명 한 단어로 셀러가 선별 절감을 0으로 만들 수 있다. `triage-only` 모드도 같은 술어를
보므로 두 모드의 분모가 같다.

**승급 판정을 TRIAGE 관점 행의 유무로 역추론하지 않는다.** 승급 경로에도 행이 남기 때문이다
(`UNCHECKED` + `PROMOTED`). 행의 `outcome`이 근거다. 끊긴 호출은 `PROMOTED`가 아니라 `FAILED`로
센다 — 모델이 "더 보라"고 판단한 것과 아무 답도 못 한 것을 분자에서 뭉개면 1순위 지표를
믿을 수 없다. 다만 표에서는 `TRUNCATED`를 `선별 상한 초과`로 따로 센다 — 상한을 올려야 하는
신호와 레이트 리밋·예산 쪽 신호가 같은 칸에 있으면 어느 쪽인지 알 수 없다.
호출이 없는 경우도 둘로 갈린다. 선별이 꺼져 있으면 TRIAGE 행 자체가 없고(`OFF`), 규칙이
적중해 묻지 않고 승급했으면 행은 있고 사유가 `RULE_HIT`다(`SKIPPED_RULE_HIT`).
`tests/test_harness.py`가 이 분류를 전부 고정한다.

## 손익분기와 중단 규칙

전제: Sonnet5 $2/$10, Haiku4.5 $1/$5, 캐시읽기 0.1배와 쓰기 1.25배, 환율 1,400원,
접두부 약 1,200토큰, 본문 신규입력 300토큰, 출력 100토큰, 상시 트래픽에서 Sonnet 캐시는 따뜻하다고 본다.

| 구성 | 건당 | 손익분기 승급률 |
|---|---|---|
| 기준선 — Sonnet 2관점 | 5.15원 | — |
| 접두부 재사용(캐시가 무시된 현실) | 2.80원 | 45.7% |
| **채택안 — 전용 짧은 프롬프트, 캐시 없음** | **1.96원** | **62.0%** |
| 접두부를 4,200토큰으로 패딩, 캐시가 따뜻할 때 | 1.71원 | 66.8% |
| 같은 것, 캐시가 차가울 때 | 8.47원 | 기준선보다 비싸다 |

승급률 60%일 때 총비용은 채택안이 2% 절감으로 사실상 0이고, 30%면 32% 절감이다.

**중단 규칙: 측정 승급률이 62.0%를 넘으면 `enable_triage`를 켜지 않는다.** 그 위에서 선별은
비용을 늘리는 기능이다. 선별 실패율이 높을 때도 같다 — 실패는 전건 승급이라 선별 호출값이
그냥 더해진다.

**위 표의 토큰 전제(1,200 / 600 / 300)는 가정이고 `--count-tokens`는 그것을 치환하지 않는다.**
치환하려면 출력 토큰 전제까지 같이 재야 하고 그건 실호출이다. `--count-tokens`가 하는 일은
접두부의 실제 토큰 수를 재서 캐시 하한을 단언하는 것뿐이고(미달이면 종료 코드 1), 측정값과
가정값을 나란히 찍는다. **어긋나면 이 표를 손으로 고쳐야 한다** — 손익분기 62.0%는 측정 뒤에도
가정값 위에 남아 있다(`1 - 1400/3680 = 0.6196`으로 역산된다).

## 캐시에 대해 알아 둘 것

- Haiku 4.5의 **최소 캐시 접두부는 4,096토큰**이다. `POLICY_PREFIX`는 2,617자로 거기에 한참
  못 미치고, Haiku에 `cache_control`을 붙이면 **에러 없이 조용히 무시된다.** 그래서 선별은
  전용 프롬프트를 쓰고 캐시 지점을 아예 붙이지 않는다.
- Sonnet 5의 최소치는 **1,024토큰**이다. **접두부의 토큰 수는 아직 실측되지 않았다** —
  2,617자는 글자 수다. 미달이면 에러 없이 캐시가 죽어 관점 호출 비용이 조용히 두 배 가까이
  뛰고, 위 손익분기표 전체가 그 숫자 위에 서 있다. `--count-tokens`가 하한을 단언하지만
  키가 필요해서 CI(`ruff check` + `pytest -q`)에는 없다. **표를 믿기 전에 한 번 돌릴 것.**
- **재는 대상이 `POLICY_PREFIX` 문자열이 아니다.** 캐시 렌더 순서가 `tools → system → messages`
  이고 `cache_control`이 마지막 system 블록에 있어서 **tools가 함께 캐시된다.** `findings_tool`은
  관점마다 enum이 달라 tools가 다르므로 **캐시 엔트리가 관점별로 갈라진다.** `--count-tokens`는
  관점별 접두부(tools+system)를 따로 재고, 선별 접두부도 같은 방식으로 잰다.
  즉 차가울 때 접두부 쓰기는 관점 수만큼 난다 — 직렬 실행이 그것을 아껴 주지 않는다.
- 캐시는 모델 범위다. Sonnet의 네임스페이스를 Haiku가 재활용할 수 없다.
